판정: KServe가 BentoML과 Yatai를 대체하는 범위

도시락 포장 공방과 매장 운영자를 구분하듯, BentoML은 모델·코드·의존성·API 로직을 Bento에 묶는 도구이고 Yatai는 그 패키지를 저장·이미지화·쿠버네티스에 배포하는 기존 체계입니다. KServe는 원하는 모델과 실행 환경을 선언하면 쿠버네티스 리소스를 조정하는 서빙 제어 도구입니다. 따라서 ‘Yatai의 배포 역할을 대체한다’와 ‘Bento 개발 방식이 그대로 보존된다’는 다른 주장입니다.

비교 기준 BentoML 1.1.x + Yatai 1.1.x 원문 경로 KServe + MLflow 경로와 대체 조건
패키징 Bento에 모델·서비스·의존성과 빌드 설정을 묶습니다. MLflow 모델 패키지 + 고정 런타임 이미지 + 배포 명세를 함께 버전 관리해야 같은 재현 단위를 구성합니다.
MLflow 레지스트리 승인 모델을 Bento 스토어로 import하고 Bento를 다시 빌드합니다. alias를 버전·실제 storage URI로 해석하여 배포합니다. KServe가 registry를 대신하지는 않습니다.
배포 단위 BentoRequest/Bento/BentoDeployment와 이미지 빌더입니다. ServingRuntime/ClusterServingRuntime과 InferenceService입니다. CRD 이름과 API는 호환되지 않습니다.
오토스케일 원문 API·Runner를 각각 확장하고 HPA를 설정합니다. Standard의 HPA/KEDA 또는 Knative의 요청 기반 확장입니다. CPU HPA에는 자원 requests와 metrics-server가 필요합니다.
scale-to-zero 원문 1.x HPA min 1 예제는 HTTP 0→1 기능을 입증하지 않습니다. Knative는 요청에 따른 0→1을 지원합니다. Standard HTTP 요청의 scale-from-zero는 현재 공식 문서상 지원되지 않습니다.
카나리·롤아웃 Yatai 배포 설정·revision과 앱 갱신 체계를 사용합니다. Standard는 Deployment 롤링 갱신이 기본입니다. 카나리 지원은 버전과 네트워크 조건에 따라 다르므로 설치 버전의 canary 문서를 확인하세요. v0.20.0에는 spec.canary가 있지만 Knative와 같은 설정이라고 가정하지 않습니다.
멀티모델·런타임 Bento 서비스 로직·Runner 조합으로 구성합니다. 여러 runtime과 ModelMesh 등 별도 모드를 사용할 수 있습니다. ModelMesh는 단일 InferenceService와 별도 운영 경로입니다.
전처리·후처리 Python API 안에 Feast 조회·전처리·응답 변환을 넣기 쉽습니다. MLflow pyfunc/Pipeline, KServe transformer, 커스텀 predictor로 구현합니다. 데이터 계약을 새로 확인해야 합니다.
요청 규격 원문 /predict에 user_id를 받아 범주를 반환합니다. 공식 MLServer 예는 V2 프로토콜, 원문 커스텀 runtime은 MLflow /invocations입니다. URL만 바꾸면 같은 API가 되지 않습니다.
모니터링·로그 BentoML /metrics와 수집 로직을 제공합니다. 서버별 metrics와 Prometheus/OpenTelemetry, 요청 로깅을 별도로 구성합니다. KServe 배포만으로 Evidently 보고서가 생기지 않습니다.
드리프트 MonitoringService가 요청 피처를 모아 Evidently에 보냅니다. 같은 수집·버퍼·주기·기준 데이터 기능을 gateway/transformer/job으로 옮겨야 합니다.
운영 부담 Yatai·DB·S3·image-builder·deployment·cert-manager·registry 등입니다. Standard 최소 경로는 KServe·cert-manager·MLflow·DB·S3이며, 외부 접속 시 gateway/ingress가 추가됩니다. Knative 모드는 구성요소가 늘어납니다.
개발자 경험 Bento의 빌드·로컬 실행·API 문서·일관된 배포물 흐름이 강점입니다. Kubernetes·runtime·URI·Secret을 이해해야 합니다. 플랫폼 팀이 템플릿을 제공하면 앱 개발자 부담을 줄일 수 있습니다.
재현 빌드 고정 Bento 태그에 코드와 모델이 연결됩니다. 모델 버전·runtime digest·설정·전처리 코드·데이터 digest를 묶어 배포 기록을 남겨야 합니다. 런타임 pip만 쓰면 네트워크 의존성이 남습니다.
유지보수 Yatai 본체 최신 release v1.1.13은 2023-10-09, 본체 저장소는 archived=true입니다. KServe latest release는 2026-11-07 확인 기준 v0.21.0, 2026-09-25입니다. 단, image-builder 별도 저장소는 v3.0.48, 2026-10-23이고 archived=false이므로 ‘Yatai 관련 도구 전부 2023년 중단’은 틀립니다.
실제 근거 CH6의 Bento 서빙·Yatai 배포·드리프트는 과거 실행 기록입니다. guide 시나리오 7의 Standard/custom runtime은 champion 모델과 HTTP 예측값 일치를 기록했습니다. 이 사례는 원문의 과거 기록입니다.

판정: 조건부 대체 가능 — 이유 3가지: ① KServe·MLflow가 등록→서빙 역할을 나눠 수행하고 원문에 성공 사례가 있습니다; ② 학습과 같은 런타임·전처리·API 계약을 고정해야 합니다; ③ Champion 재배포와 드리프트 수집을 추가해야 하며 HTTP scale-to-zero가 필요하면 Knative 경로를 선택해야 합니다.

대체 조건 네 가지

  1. alias를 불변 버전과 실제 S3 URI로 해석하고, 승인 후 배포 갱신·롤백을 CI/CD로 연결합니다.
  2. 모델 패키지와 런타임의 Python·라이브러리·이미지 버전을 맞춥니다.
  3. 피처 조회·전처리·응답 변환을 pyfunc 또는 transformer/API 어댑터로 옮겨 기존 계약을 보존합니다.
  4. 팀이 인증서·쿠버네티스·저장소·네트워크 운영을 맡습니다. HTTP scale-to-zero가 필요하면 Knative 구성을 선택합니다.
⚠ 원문 정정: Yatai 본체는 2026-06-11 보관 처리되었지만 관련 모든 저장소가 같은 시점에 멈춘 것은 아닙니다. yatai-deployment의 별도 최신 릴리스는 v1.1.21입니다. BentoML의 Python 개발 경험과 Bento 패키징은 별도의 장점으로 남습니다.

목표 아키텍처와 실행 경로

기본 경로는 CPU 기반 단일 사용자 실습입니다. 내 PC(macOS·Linux)에서는 kind, 원격 서버나 Ubuntu 서버에서는 k3s 중 하나만 고릅니다. SeaweedFS·PostgreSQL·MLflow·KServe를 올리고, Adult의 원문과 같은 여덟 범주형 열로 모델을 학습합니다. 모델 안에 전처리를 포함시켜 호출자가 원문 예의 90열을 직접 만들 필요를 줄입니다. 이것은 원문의 XGBoost-only 90열 API에 대한 명시적인 보강이며 입력 계약이 달라집니다. 원문 그대로 비교하려면 뒤의 원문 재현 분기를 사용합니다.

기본 실습에서 서비스 내부 포트는 표에 적은 설계 상수이며 원문의 개인 NodePort를 그대로 사용하지 않습니다. 포트포워드는 로컬 루프백에만 연결합니다. 외부 gateway·TLS·인증·다중 노드·백업·고가용성은 운영 확장 조건이며 이 단일 노드 예제의 달성 결과로 주장하지 않습니다.

🎯 목적

작업실의 공구·주소·열쇠를 먼저 정하듯, 도구와 실행 위치를 고정하여 다른 클러스터나 포트에 명령을 보내는 실수를 줄입니다. 기본 경로의 학습은 CPU로 가능하며 GPU가 필수는 아닙니다. 최소 실습 예산은 클러스터 CPU 4개·RAM 8~12Gi·여유 디스크 40Gi 정도에서 시작하되 패키지 빌드와 동시 실행을 줄입니다. 권장은 CPU 8개·RAM 16Gi 이상·여유 디스크 60Gi입니다. 전체 Kubeflow·GitOps·Notebook·Feast까지 원문처럼 설치하려면 RAM 24~32Gi 이상을 권장하며 실제 사용량을 측정해야 합니다. 이 수치는 실행 입증값이 아닙니다.

SSH 터널은 원격 서비스가 이미 해당 포트에서 살아 있어야 작동합니다. 불필요한 NodePort나 공개 IP 바인딩을 추가할 필요는 없습니다.

A-1. 전용 클러스터 준비

🎯 목적

모델 서비스가 실행될 작업 공간을 만듭니다. Kubernetes는 컨테이너의 배치·복구·상태 관리를 담당합니다. 기본 경로는 kind와 k3s 중 하나입니다.

📋 사전조건

도구·Docker, 충분한 CPU·메모리·디스크 여유(E-02)와 A-0 환경 파일이 준비되어야 합니다. 기존 공유 클러스터를 변경하지 않습니다. 여러 사람이 함께 쓰는 서버라면 k3s를 설치하기 전에 관리자에게 먼저 확인하세요. 이미 적절한 전용 클러스터가 있다면 생성 대신 context와 버전만 확인합니다.

⌨ 명령어

[PC 또는 원격 터미널 1: macOS 또는 Linux kind 분기]

cd "$HOME/ml-serving-lab"
. ./lab.env
kind create cluster --name "$CLUSTER_NAME" --image "$KIND_NODE_IMAGE" --wait 300s
kubectl config use-context "$CONTEXT"
kubectl wait node --all --for=condition=Ready --timeout=300s

[원격/Ubuntu 터미널 1: 새 전용 k3s 서버 분기]

cd "$HOME/ml-serving-lab"
. ./lab.env
curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION="$K3S_VERSION" sh -s - server --disable traefik
sudo k3s kubectl get nodes
sudo install -m 600 /etc/rancher/k3s/k3s.yaml "$WORK_ROOT/kubeconfig"
sudo chown "$USER" "$WORK_ROOT/kubeconfig"
export KUBECONFIG="$WORK_ROOT/kubeconfig"
printf '%s\n' 'export KUBECONFIG="$WORK_ROOT/kubeconfig"' >> lab.env
kubectl config current-context
kubectl wait node --all --for=condition=Ready --timeout=300s

k3s 분기를 썼다면 바로 위 마지막 줄 kubectl config current-context가 출력한 이름(보통 default)을 CONTEXT에 넣어야 합니다. 아래 두 줄이 그 일을 합니다. kind 분기를 썼다면 이 줄은 건너뜁니다.

[원격/Ubuntu 터미널 1: k3s 분기일 때만, context와 StorageClass 맞추기]

sed -i.bak "s|^export CONTEXT=.*|export CONTEXT='$(kubectl config current-context)'|" lab.env
sed -i.bak "s|^export STORAGE_CLASS=.*|export STORAGE_CLASS='local-path'|" lab.env
. ./lab.env
echo "CONTEXT=$CONTEXT STORAGE_CLASS=$STORAGE_CLASS"

위 kubeconfig는 원격에서 사용하는 분기입니다. PC에 복사하면 server의 루프백 주소와 인증서 SAN 문제까지 처리해야 하므로 기본 경로는 SSH로 원격에서 kubectl을 실행합니다.

class IncomeProbability(mlflow.pyfunc.PythonModel):

from pathlib import Path
import boto3, joblib, mlflow, numpy as np, pandas as pd
from botocore.config import Config

columns = ['age', 'Workclass', 'fnlwgt', 'Education', 'education-num',
           'Marital-Status', 'Occupation', 'Relationship', 'Race', 'Sex',
           'capital-gain', 'capital-loss', 'hours-per-week', 'Native_country', 'Target']

            'Relationship', 'Race', 'Sex', 'Native_country']
url = os.environ['ADULT_DATA_URL']

for c in data.columns:
    data[c] = data[c].str.strip()
data = data.loc[~data.eq('?').any(axis=1)].reset_index(drop=True)
y = data.Target.eq('>50K').astype(int)
X = data[features]
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, random_state=seed, stratify=y)
train_df = X_train.assign(Target=y_train)
test_df = X_test.assign(Target=y_test)
X.to_csv(os.environ['REFERENCE_FILE'], index=False)
s3 = boto3.client('s3', endpoint_url=os.environ['PC_S3_URL'],
                 config=Config(s3={'addressing_style': 'path'}))
name = os.environ['MODEL_NAME']
bucket = os.environ['S3_DATA_BUCKET']
sources = {}
for label, df in [('train', train_df), ('test', test_df), ('features', X)]:
    body = df.to_csv(index=False).encode()
    digest = hashlib.sha256(body).hexdigest()
    key = f'{name}/datasets/{label}-{digest}.csv'
    s3.put_object(Bucket=bucket, Key=key, Body=body)
    sources[label] = f's3://{bucket}/{key}'
mlflow.set_tracking_uri(os.environ['PC_MLFLOW_URL'])
mlflow.set_experiment(name)
candidates = {
    'decision-tree': DecisionTreeClassifier(max_depth=10, random_state=seed),
    'random-forest': RandomForestClassifier(n_estimators=100, max_depth=10,
                                           random_state=seed, n_jobs=1),
    'xgboost': XGBClassifier(n_estimators=100, max_depth=10, random_state=seed,
                            n_jobs=1, eval_metric='logloss')}
results = []
for kind, estimator in candidates.items():

        ('encode', ColumnTransformer([('categorical', OneHotEncoder(
            handle_unknown='ignore', sparse_output=False), features)])),
        ('classifier', estimator)])
    with mlflow.start_run(run_name=kind) as run:
        pipeline.fit(X_train, y_train)
        prob = pipeline.predict_proba(X_test)[:, 1]
        auc = roc_auc_score(y_test, prob)
        accuracy = accuracy_score(y_test, prob >= 0.5)
        mlflow.log_params({'model_type': kind, 'seed': seed, 'test_size': 0.2,
                           'max_depth': 10, 'input_contract': 'Adult8-to-probability'})
        mlflow.log_dict(estimator.get_params(), 'estimator_params.json')
        mlflow.log_metrics({'roc_auc_score_test': auc, 'accuracy_score_test': accuracy})
        mlflow.set_tag('source_ref', os.environ['SOURCE_REF'])
        for label, df, context in [('train', train_df, 'training'),
                                    ('test', test_df, 'testing'), ('features', X, 'reference')]:
            ds = mlflow.data.from_pandas(df, source=sources[label], name=label,
                                        targets='Target' if label != 'features' else None)
            mlflow.log_input(ds, context=context)
        mlflow.log_dict(sources, 'dataset_sources.json')
        mlflow.log_dict(features, 'input_columns.json')
        mlflow.log_artifact('training-requirements.lock', artifact_path='source')
        mlflow.log_artifact('train.py', artifact_path='source')
        mlflow.log_artifact('income_model.py', artifact_path='source')
        artifact = Path(f'{kind}.joblib'); joblib.dump(pipeline, artifact)
        example = X_test.head(3).reset_index(drop=True)
        model = mlflow.pyfunc.log_model(
            name='model', python_model=IncomeProbability(),
            artifacts={'pipeline': str(artifact)}, code_paths=['income_model.py'],
            input_example=example, signature=infer_signature(example, prob[:3]),
            pip_requirements='training-requirements.lock')
        mlflow.set_tag('model_uri', model.model_uri)
        results.append({'type': kind, 'auc': float(auc), 'accuracy': float(accuracy),
                        'run_id': run.info.run_id, 'model_uri': model.model_uri})
best = max(results, key=lambda r: r['auc'])
version = mlflow.register_model(best['model_uri'], name)
client = MlflowClient()
client.set_registered_model_alias(name, os.environ['MODEL_ALIAS'], version.version)
client.set_model_version_tag(name, version.version, 'approved_run_id', best['run_id'])
Path('training_result.json').write_text(json.dumps(
    {'candidates': results, 'champion': best, 'version': version.version}, indent=2))

print('등록 완료:', name, 'version', version.version, 'alias', os.environ['MODEL_ALIAS'])

from pathlib import Path
from urllib.parse import urlparse
import boto3, mlflow
from mlflow import MlflowClient
from botocore.config import Config
mlflow.set_tracking_uri(os.environ['PC_MLFLOW_URL'])
client = MlflowClient()
name, alias = os.environ['MODEL_NAME'], os.environ['MODEL_ALIAS']
v = client.get_model_version_by_alias(name, alias)
source = v.source
if not source or not isinstance(source, str):
    raise RuntimeError('모델 source가 비어 있습니다.')
model_id = ''
if source.startswith('models:/m-'):
    model_id = source.removeprefix('models:/')
    artifact_uri = mlflow.get_logged_model(model_id).artifact_location
elif source.startswith('runs:/'):
    run_id, path = source.removeprefix('runs:/').split('/', 1)
    artifact_uri = client.get_run(run_id).info.artifact_uri.rstrip('/') + '/' + path
else:
    artifact_uri = source
bucket = os.environ['S3_BUCKET']
if artifact_uri.startswith('mlflow-artifacts:/'):
    # A-3의 --artifacts-destination이 이 버킷 루트인 경우에만 이 변환이 맞습니다.
    storage_uri = 's3://' + bucket + '/' + artifact_uri.removeprefix('mlflow-artifacts:/').lstrip('/')
elif artifact_uri.startswith('s3://'):
    storage_uri = artifact_uri
else:
    raise RuntimeError('이 기본 경로가 지원하지 않는 artifact scheme: ' + artifact_uri)
u = urlparse(storage_uri)
if not u.netloc or not u.path.strip('/'):
    raise RuntimeError('모델 디렉터리 URI가 비어 있습니다.')
if u.netloc != bucket:
    raise RuntimeError('A-3 설정 버킷과 다릅니다. 실제 artifact 저장소 설정을 확인하십시오.')
s3 = boto3.client('s3', endpoint_url=os.environ['PC_S3_URL'],
                 config=Config(s3={'addressing_style': 'path'}))
for filename in ['MLmodel', 'requirements.txt']:
    s3.head_object(Bucket=u.netloc, Key=u.path.strip('/') + '/' + filename)
values = {'MODEL_VERSION': v.version, 'RUN_ID': v.run_id or '', 'MODEL_ID': model_id,
          'ARTIFACT_URI': artifact_uri, 'STORAGE_URI': storage_uri,
          'MODEL_URI': f'models:/{name}/{v.version}'}
with Path('lab.env').open('a') as f:
    for key, value in values.items():
        f.write(f'export {key}={shlex.quote(str(value))}\n')
print('고정 버전:', v.version, 'MLmodel·requirements.txt 존재 확인 완료')

대안: 원문처럼 파드가 뜰 때 의존성을 설치하는 방식

언제 쓰나요? 모델마다 필요한 라이브러리 버전이 달라서, 이미지를 하나로 고정하기 어려울 때입니다. 원문은 모델 폴더에 함께 저장된 requirements.txt를 파드가 시작할 때 설치한 뒤 서버를 실행했습니다. 학습 때 쓴 xgboost 같은 라이브러리 버전을 서빙에서도 똑같이 맞추려는 의도입니다.

기본 경로와 무엇이 다른가요? 기본 경로는 같은 requirements.txt를 이미지를 만들 때 한 번 설치합니다. 대안은 파드가 시작할 때마다 설치합니다. 대신 아래 세 가지를 감수해야 합니다.

항목이미지에 미리 설치(기본)시작 때 설치(대안)
파드 시작 시간빠릅니다설치 시간만큼 늦어집니다(원문은 약 2~3분)
네트워크이미지 빌드 때만 필요파드가 뜰 때마다 패키지 저장소 접속이 필요
환경 재현성이미지 digest로 고정저장소 상태에 따라 달라질 수 있음

ServingRuntime의 command와 args 부분만 아래처럼 바꿉니다. 나머지 필드는 위 매니페스트와 같습니다. ${BIND_ALL}은 설정값 표에 정의된 값입니다.

    command: [/bin/sh, -c]
    args:

    - pip install --no-cache-dir -r /mnt/models/requirements.txt && exec mlflow models serve -m /mnt/models -h ${BIND_ALL} -p 8080 --env-manager local

exec를 쓰는 이유는 셸이 mlflow 프로세스로 교체되어 이 프로세스가 컨테이너의 PID 1이 되게 하려는 것입니다. 이렇게 해야 파드가 종료 신호를 서버에 제대로 전달합니다. 이 방식은 컨테이너가 외부 패키지 저장소에 접속할 수 있어야 하므로, 폐쇄망이면 기본 경로를 쓰세요.

⚠ 주의: 이 대안은 이 가이드의 기본 경로로 검증된 것이 아니라 원문 방식을 옮겨 적은 것입니다. 시작 시간이 길어지면 readinessProbe의 initialDelaySeconds도 설치 시간에 맞게 늘려야 합니다.

import json, os, subprocess, time
ns, name = os.environ['NS'], os.environ['MODEL_NAME']
uri = os.environ['STORAGE_URI']
selector = 'serving.kserve.io/inferenceservice=' + name
deadline = time.monotonic() + 600
while time.monotonic() < deadline:
    raw = subprocess.check_output([
        'kubectl', '-n', ns, 'get', 'deploy', '-l', selector, '-o', 'json'])
    deployments = json.loads(raw)['items']
    matched = [d for d in deployments if uri in json.dumps(d['spec']['template'])]
    if len(matched) == 1:
        deployment = matched[0]['metadata']['name']
        subprocess.run(['kubectl', '-n', ns, 'rollout', 'status',
                        'deployment/' + deployment, '--timeout=600s'], check=True)
        print('새 URI를 포함한 Deployment 롤아웃 완료:', deployment)
        break
    time.sleep(3)
else:
    raise TimeoutError('새 URI가 Deployment 템플릿에 반영되지 않았습니다.')

[PC 또는 원격 터미널 1: Kubernetes 자원 검사]

kubectl top nodes
kubectl -n "$NS" top pods
kubectl -n "$NS" get events --sort-by=.lastTimestamp
kubectl describe nodes

top가 Metrics API not available이면 metrics-server 설치/상태를 확인합니다. [Ubuntu/원격 호스트]에서는 free -h, df -h, [macOS 호스트]에서는 Activity Monitor·Docker Desktop 자원 설정으로 확인합니다. CPU throttling, OOMKilled, Pending, PVC 사용량, /ping 성공률, HTTP p95 지연을 단계 게이트에 포함합니다. 초기 예산은 시작점이며 사용량과 지연은 실제 환경에서 측정해야 합니다.

E-03. 처음 따라 할 때 자주 만나는 증상

위 E-01 표는 원인별 점검 순서이고, 아래는 이 가이드를 처음부터 따라 할 때 흔히 만나는 증상을 한곳에 모았습니다.

증상 가장 흔한 원인 확인과 해결
ImagePullBackOff, ErrImagePull 이미지를 노드에 넣지 않았거나 태그 오타, CPU 아키텍처 불일치 kubectl describe pod의 Events를 읽습니다. 직접 빌드한 이미지는 kind/k3s 노드로 가져오는 단계(import/load)를 했는지 확인합니다. 직접 빌드하지 않은 이미지(SeaweedFS·PostgreSQL·KServe 등)가 계속 실패하면 서버나 PC의 인터넷 연결, 회사 프록시, 레지스트리 내려받기 횟수 제한을 Events 메시지로 확인합니다.
exec format error IMAGE_PLATFORM이 내 CPU와 다름 uname -m이 arm64/aarch64면 linux/arm64, x86_64면 linux/amd64인지 lab.env에서 확인하고 이미지를 다시 빌드합니다.
파드가 Pending에서 멈춤 PVC를 만들 StorageClass가 없거나 이름이 다름 kubectl get storageclass의 (default) 이름이 lab.env의 STORAGE_CLASS와 같은지 확인합니다(A-1).
서버가 떴는데 Ready가 안 됨, 연결 거부 BIND_ALL이 0.0.0.0이 아님 echo $BIND_ALL이 0.0.0.0인지 확인합니다. localhost나 빈 값이면 lab.env를 고치고 해당 파드를 다시 만듭니다.
command not found: brew (macOS) Homebrew를 방금 설치해 현재 터미널이 위치를 모름 A-0의 brew shellenv 줄(/opt/homebrew/bin/brew shellenv)을 실행하고 brew --version을 확인합니다.
command not found: uv (Ubuntu) uv가 $HOME/.local/bin에 설치되어 현재 PATH에 없음 export PATH="$HOME/.local/bin:$PATH" 후 uv --version. 새 터미널마다 필요하면 ~/.bashrc에 같은 줄을 추가합니다.
command not found: kind / kubectl / helm (Ubuntu) 설치 블록을 건너뛰었거나 실패함 command -v kind, command -v kubectl, command -v helm으로 도구를 하나씩 확인하고, 비어 있는 것의 A-0 설치 블록을 다시 실행합니다. kind·kubectl은 /usr/local/bin, uv는 $HOME/.local/bin에 설치됩니다.
Cannot connect to the Docker daemon Docker가 아직 켜지는 중이거나 꺼져 있음 macOS는 Docker Desktop이 Engine running인지 확인합니다. Ubuntu는 sudo systemctl status docker로 확인하고, 그룹 적용 전이면 로그아웃 후 다시 로그인합니다.
permission denied ... docker.sock docker 그룹 적용 전 usermod 뒤에 SSH 또는 터미널을 닫고 다시 접속한 뒤 docker info를 실행합니다(A-0).
context "..." does not exist lab.env의 CONTEXT가 실제와 다름 kubectl config current-context 결과를 CONTEXT에 넣습니다(k3s는 보통 default, A-1).
Could not connect to the endpoint URL 포트포워드 창(2, 3)이 꺼짐 해당 창에서 A-3의 포트포워드 블록을 다시 실행합니다. 원격이면 SSH 터널(창 6)도 살아 있는지 봅니다. 서버 SSH 창이 끊기면 그 창의 포트포워드도 함께 종료되므로, 다시 접속해 cd "$HOME/ml-serving-lab", . ./lab.env 뒤 포워딩 블록을 다시 실행합니다.
address already in use 같은 포트를 다른 프로그램이 사용 중 표의 *_PC_PORT를 비어 있는 포트로 바꾸고 lab.env, SSH 터널을 함께 맞춥니다. macOS는 5000 포트를 AirPlay가 쓰므로 이 가이드는 15000을 씁니다.
파드나 docker build 안에서만 인터넷이 안 됨 (timeout, name resolution) 방화벽(ufw 등)이나 DNS 설정이 컨테이너 통신을 막는 경우가 있습니다(문서 밖 일반 지식, 추정) 방화벽이 켜져 있다면 sudo ufw status로 상태를 확인하고, 원인이라고 확인되기 전에는 방화벽을 끄지 않습니다. docker run --rm busybox nslookup github.com으로 컨테이너 DNS를 먼저 확인합니다.
kubectl top이 Metrics API not available metrics-server가 없음 이 실습의 필수 단계가 아닙니다. k3s는 기본 포함, kind는 따로 설치해야 하며 자원 관찰용으로만 쓰입니다.

E-04. 정리하기 전에 확인할 것

A-9에서 서빙만 종료할지, 전용 namespace를 삭제할지, 직접 만든 kind 클러스터까지 없앨지 선택합니다. DB·S3·PVC·보고서·환경 lock의 보존 여부를 먼저 정하세요. chart·CRD·cert-manager와 외부 registry 이미지가 부분 정리 뒤 남는지도 확인합니다.
