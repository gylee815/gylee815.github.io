apt install tree git jq yq unzip vim sshpass -y -qq >/dev/null 2>&1

echo "root:qwe123" | chpasswd

cat << EOF >> /etc/ssh/sshd_config
PasswordAuthentication yes
PermitRootLogin yes
EOF
systemctl restart sshd  >/dev/null 2>&1

echo "[TASK 7] Setting Local DNS Using Hosts file"
sed -i '/^127\.0\.\(1\|2\)\.1/d' /etc/hosts

  • (참고) system:masters 그룹에 속한 사용자 특징 : 인증 후 → 인가 우회. 즉, 인증 시 바로 슈퍼유저 권한 - Docs
    • RBAC 기반 권한검사(Role/ClusterRole)를 거치지 않음. 웹훅 기반 인가도 거치지 않음.
    • 즉, API 서버에서 모든 동작을 무조건 허용함. 실질적으로 클러스터 슈퍼유저(superuser) 권한
    • The system:masters group is a built-in Kubernetes group that grants unrestricted access to the API server. Any user assigned to this group has full cluster administrator privileges, bypassing any authorization restrictions imposed by the RBAC or Webhook mechanisms. Avoid adding users to this group. If you do need to grant a user cluster-admin rights, you can create a ClusterRoleBinding to the built-in cluster-admin ClusterRole.
    • system:masters 그룹은 API 서버에 대한 무제한(superuser) 접근 권한을 부여하는 내장(built-in) 그룹.
    • 이 그룹에 속한 사용자는 모든 요청에 대해 RBAC이나 Webhook 같은 인가(authorization) 검사를 받지 않고 API 접근을 허용받음.
    • 따라서 일반적인 RBAC 정책(ClusterRole, ClusterRoleBinding)과 상관 없이 전체 클러스터에 대한 관리자 권한을 갖습니다 → 즉 인가 검증이 사실상 우회됨.
    • 공식 체크리스트에서도 이 그룹의 사용은 최소화하라고 권고. (부트스트랩 이후에는 사용자/컴포넌트에 system:masters 인증 정보로 접근하지 않아야 함) → AWS Root 계정과 유사하게 관리
      • 관리자 인증서가 탈취당하면 복구가 매우 어려움

    • kube-controller-manager
      • -allocate-node-cidrs=true 옵션은 클러스터 전체의 Pod IP 대역(-cluster-cidr)을 각 개별 노드(Node)에 쪼개서 할당해 주는 기능을 활성화하는 설정입니다.

      이 라인이 있고 없고의 차이점은 다음과 같습니다.

      1. 설정이 있을 때 (true)

      • 동작: kube-controller-manager가 새 노드가 클러스터에 참여할 때마다 전체 대역(예: 10.200.0.0/16)에서 특정 부분(기본적으로 노드당 /24 대역)을 떼어 해당 노드의 전용 Pod 대역(podCIDR)으로 지정합니다.
      • 결과: 각 노드의 상세 정보(kubectl get node -o yaml)를 확인해 보면 spec.podCIDR: 10.200.x.0/24와 같은 값이 자동으로 채워집니다.
      • CNI와의 관계: 노드에 할당된 이 podCIDR 정보를 기반으로 CNI 플러그인(bridge, flannel 등)이 Pod에 부여할 실제 IP 주소를 관리할 수 있게 됩니다.

      2. 설정이 없을 때 (false, 기본값)

      • 동작: kube-controller-manager는 각 노드에 IP 대역을 할당하는 작업을 수행하지 않습니다.
      • 결과: 노드의 spec.podCIDR 필드가 비어 있게(null) 됩니다.
      • 에러 발생: 질문하신 상황처럼 kubelet이 Pod를 띄우려고 할 때 CNI 플러그인이 "이 노드에서 사용할 IP 대역(CIDR)이 무엇인가?"라고 묻지만, 할당된 값이 없으므로 invalid CIDR address 또는 failed to parse cidr value:"" 같은 에러를 내뱉으며 멈추게 됩니다.

      1. 왜 수동 설치 시 중요한가요?

        kubeadm 같은 자동화 도구는 네트워크 설정을 감지하여 이 옵션을 자동으로 켜주지만, 직접 바이너리로 서비스를 등록할 때는 명시하지 않으면 비활성화 상태가 됩니다.

        따라서 직접 클러스터를 구축하고 bridge 방식의 CNI를 사용한다면, 컨트롤러 매니저가 노드별로 주소를 분배해 주는 이 옵션이 반드시 필요합니다.
